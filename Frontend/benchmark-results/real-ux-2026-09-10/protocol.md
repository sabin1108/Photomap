# 사전 실행 범위 (2026-09-10)

원 설계: source/requested-design.md. 이 파일은 실제 사진 결과를 보기 전에 작성했다.

- A=같은 PhotoFeed의 모든 행 렌더링, B=기존 가상화(estimateSize 200, overscan 5).
- 핵심 셀: 독립 PhotoFeed, 서로 다른 실제 사진 1000개, Chromium 390×844 DPR2, CPU 감속 없음, warm. click/scroll 각각 파일럿 5쌍, 본 실험100쌍.
- 확장 셀: 사진 원본1000개를 반복한 항목3000개, CPU4배 감속, warm, click 파일럿5쌍 및 본 실험100쌍. 기본 셀과 합산하지 않는다. 성능을 고의 지연하는 busy loop는 추가하지 않는다.
- cold 및 전체 앱은 별도 탐색/기능 검증. 실제 Android/외부 카메라/사용자 평가 자료가 없으면 미실시로 남긴다.
- 캡처 진단은 시간 본 실험과 분리. 캡처상 표시 관측과 코드상 준비를 구별한다. 외부 디스플레이 표시나 INP라고 부르지 않는다.
- 기본 클릭 코드준비 보조지표, scroll LoAF 합계를 측정하며, 표시 주지표는 캡처 실험에서만 판단한다. 실용적 표시 지연 후보 차이는50ms. 코드준비 결과에 해당 기준을 대입해 사용자 체감 개선을 단정하지 않는다.
- 순서는 각 runner의 seed 기반 균형 AB/BA. 개별 실행 전 protocol-lock/schedule/source hashes 저장. 실패/무효/재실행을 덮어쓰지 않는다.
- 개선 없음과 악화도 보고한다. 0 LoAF는 이 조건에서 프리즈 감소 증거 없음. 실기기/참여자 미실시는 자동화로 대체하지 않는다.
- 기기 온도 센서 사용 가능성이 확인되지 않아 온도 통제는 보장하지 않는다. 전원 설정 고성능 기록, 실행은 한 번에 하나. 워밍업과 실행 간 대기시간을 원시 프로토콜로 보존한다.
