# 2026-07-21 LCP 최적화 기록

측정 대상은 `https://photomap-three.vercel.app/` 하나로 고정한다. 로컬 Lighthouse 값은 비교 기준으로 쓰지 않는다.

## 문제

Vercel 기준 LCP 후보는 `Bangkok Night Road` 이미지였다. 기존 `PhotoFeed`는 above-the-fold 이미지에 이미 `loading="eager"`와 `fetchpriority="high"`를 주고 있었다. 그런데 Lighthouse의 LCP discovery 항목은 `Request is discoverable in initial document = false`였다.

즉 병목은 이미지 태그의 priority 누락이 아니라, 브라우저가 초기 HTML 단계에서 LCP 이미지와 Supabase media origin을 너무 늦게 알게 되는 구조였다. React 앱이 뜬 뒤 Supabase 조회가 끝나야 이미지 URL이 DOM에 나타났다.

## 조치

1. `Frontend/index.html`에 Supabase media origin `preconnect`와 `dns-prefetch`를 추가했다.
2. 현재 public demo의 LCP 이미지 URL을 `rel="preload" as="image" fetchpriority="high"`로 초기 HTML에서 발견 가능하게 했다.
3. public demo 전용 seed 사진 6장을 추가했다. 앱 초기화 시 빈 목록 대신 seed를 먼저 렌더하고, Supabase 조회가 끝나면 기존 실제 데이터로 교체한다.
4. 정적 root shell도 실험했지만 Vercel 측정에서 LCP가 악화되어 되돌렸다. React가 root를 교체하면서 의도한 초기 HTML LCP가 유지되지 않았다.

## 결과

기준값은 Vercel 3회 측정 median이다.

| 기준 | Performance | LCP | TBT | Speed Index | TTI | Payload |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 최초 Vercel baseline | 86 | 3860ms | 137ms | 3032ms | 4076ms | 368370B |
| #16 이후 LCP 작업 전 | 91 | 3459ms | 17ms | 2358ms | 3496ms | 349772B |
| preload + seed 이후 | 92 | 3280ms | 48ms | 2060ms | 3303ms | 350172B |

LCP discovery 점수는 `0`에서 `1`로 개선됐다. LCP 이미지가 초기 문서에서 발견 가능해졌다는 뜻이다.

## 판단

이번 조치는 LCP 병목 중 `이미지 발견 지연`과 `Supabase 조회 전 빈 화면`을 줄였다. 다만 median LCP는 아직 `3280ms`로, 우리가 정한 유의미한 목표인 `2500ms 이하`에는 도달하지 못했다.

따라서 이번 커밋은 LCP 일부 병목 해결이다. 사용자가 체감할 수준의 완료로 보려면 다음 단계에서 React 초기 실행 비용이나 첫 화면 렌더 경로를 더 줄여야 한다.

## 측정 정책 수정

앞으로 이슈 해결 뒤 Vercel 성능 확인은 1회 측정으로 충분하다. 단, 값이 튀거나 회귀가 의심될 때만 추가 반복 측정한다.
