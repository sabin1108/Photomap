# 공개 데모 복구 및 피드백 반영 — 2026-09-11

## 문제와 원인

일반 데모 사진과 관계 보기 사진 노드가 6개에 머물렀다. 기존 로컬 파일은 16장(display/thumb 각 16개)이었지만 초기/빈 DB 대체 목록에는 6장만 연결돼 있었다. 이번 로컬 확인에서 설정된 Supabase 호스트 조회는 ENOTFOUND로 실패했다. 이는 해당 환경에서 관측한 연결 실패이며 DB 데이터 삭제나 운영 서버 상태를 확정하는 근거는 아니다.

## 반영한 범위

- 일반 데모에 기존 로컬 이미지 16장을 모두 연결. 기존 6장 ID와 순서는 유지했다.
- 예시 카테고리와 태그를 제공해 지도·앨범·관계 탐색이 가능하도록 했다. 위치는 예시임을 본문/사진 설명에 명시했다.
- DB 설정 없음, 요청 실패, 빈 목록에서도 예시 탐색과 브라우저 즐겨찾기를 유지한다. 정상 DB 결과는 기존처럼 예시 목록을 교체한다.
- 지도와 앨범 검색을 동일한 높이·모서리·아이콘·포커스 스타일의 PhotoSearch로 연결했다. 검색어 앞뒤 공백을 정리하고 검색어 지우기 버튼을 제공한다.
- 읽기 전용 모드에서 눌러도 반응하지 않던 사진 선택 버튼을 숨겼다. 안내 문구는 실제 가능한 지도·태그·앨범·즐겨찾기 탐색을 설명한다.
- 관계 보기 노드는 Enter/Space로 태그·사진을 열 수 있고 중앙 노드로 전체 태그에 돌아갈 수 있다. 전환 중 비활성 상태를 접근성 속성으로 제공한다.
- 도시/지역을 세는 화면 수치의 단위를 countries에서 places로 바로잡았다.

## 검증

`cd Frontend; npm run test:demo`로 전용 로컬 서버를 자동 실행한다. 테스트 API 키와 사용자 ID는 가짜 값이며 요청은 브라우저에서 가로챈다.

브라우저 테스트 6개 통과:

1. DB 연결 실패에도 16개 사진 노드, 모든 노드 썸네일 정상 로드, 사진 상세 열기, 즐겨찾기 새로고침 유지.
2. DB 빈 목록에서도 위 동작 유지.
3. 정상 DB 사진 1개 응답은 예시와 섞이지 않고 실제 목록으로 교체.
4. 데스크톱에서 지도 검색/초기화와 위치·태그 앨범 표시.
5. 모바일에서 동일 흐름, 화면 캡처 확인.
6. 성능 Preview의 기존 6장 fixture 유지. 일반 데모 확장을 성능 비교 변경으로 섞지 않음.

추가 실제 지도 확인: DB 차단 상태에서 지도 마커가 표시되고 두 번째 미리보기 선택 시 '지도 이동 완료 · Singapore' 확인. 사진 상세 모달도 열렸다. 마커 수는 현재 지도 범위/렌더링 상태에 따라 다르며 전체 사진 수로 해석하지 않는다.

## 대화 피드백 중 다른 작업에 해당하는 내용

이력서 PDF 제공, 외부 포트폴리오의 문제 번호, 게임 사이트 및 채용 방향은 현재 PhotoMap 저장소 밖의 내용이다. 해당 자료는 수정하지 않았다. 원문 대화는 저장소에 복사하지 않았다.

기술 설명에 재사용할 때 주의할 사실:

- 현재 지구본 구현은 `cobe`, 관계 그래프는 D3. 둘을 three.js 구현이라고 소개하면 코드와 맞지 않는다.
- 리스트 가상화와 이미지 지연 로딩은 별도 기법이다. React Virtual DOM과 리스트 가상화를 같은 뜻으로 쓰지 않는다.
- 59.6ms는 0.0596초, 13.2ms는 0.0132초다. 수치 차이만으로 사용자 체감 개선을 입증할 수 없다.
- 일반 예시 사진 16장, 기존 성능 Preview 6장, 별도 가상화 실험 항목 1,000/3,000개는 다른 데이터 조건이다.

변경은 로컬 작업 트리에 반영했다. 운영 사이트 배포와 원격 DB 복구는 수행하지 않았다.

최종 검증: 프로덕션 빌드, TypeScript 검사, 기존 load 계약 10개, 성능/fixture 계약 7개, diff 공백 검사 통과. DB 환경변수를 모두 비운 별도 서버에서도 사진 16장·카테고리 앨범 표시 확인. 독립 읽기 검토에서 범위 내 차단 결함 없음. 별도 lint 명령은 제공되지 않음.
