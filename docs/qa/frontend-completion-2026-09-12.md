# 프론트엔드 탐색 흐름 완성 — 2026-09-12

## 이 프로젝트가 보여주는 것

**같은 사진 데이터를 여러 탐색 방식으로 연결하면서, 사용자의 맥락과 조작 가능성을 유지하는 프론트엔드 설계.**

지도·관계 그래프의 시각적 표현에 더해, 찾기 → 상세 → 좋아요 → 모아보기 → 이전 탐색 복귀가 실제로 이어진다. 기술 설명은 이 문서와 README에 두고, 제품 화면은 사용자의 행동에 집중한다. 제품 결정 기준은 [DESIGN.md](../../DESIGN.md).

## 구현과 근거

| 문제 | 구현 | 검증 |
| --- | --- | --- |
| 화면을 바꾸면 검색/앨범 조건이 사라짐 | `useExploreParam`: 화면, 지도 검색·태그·선택 위치, 앨범 검색·탭·상세, 좋아요 필터를 URL에 저장. 클릭은 push, 입력은 replace | 새로고침, 뒤로/앞으로, 기존 query 보존 |
| 돌아온 목록의 위치를 잃음 | `useScrollRestoration`: 실제 스크롤 컨테이너의 위치 저장. 피드/앨범별 키, 50개 상한 | 모바일 피드 이동 후 위치 복원 |
| 카드와 모달을 마우스로만 조작 | 사진/앨범 native button, 필터 pressed state, Radix 모달의 포커스 제한·Escape·복귀 | Enter/Space, Tab 순환, 닫기 버튼/키보드 복귀 |
| 좋아요 화면에 별도 갤러리·무동작 버튼·고정 설명 | 공유 `PhotoFeed` + `PhotoModal` 사용. 지도/피드에서 `PhotoFavoriteButton` 재사용 | 좋아요 저장, 필터, 새로고침, 해제 후 빈 결과 복구 |
| 앨범마다 전체 사진을 반복 필터링·정렬 | `buildPhotoAlbums`: 사진 순회로 그룹 개수와 최신 장소/태그 표지 계산 | 중복 태그·카테고리 중복 집계 방지, 표지 선택, 빈 앨범, 입력 불변성 |
| 좋아요 변경에도 원본 이미지 로더 재시작 | 모달 이미지 effect를 사진 객체가 아닌 preview/full URL에 연결 | 이미지 전달 계약과 기존 상세 회귀 |
| 모바일 메뉴가 소개 제목과 겹치고 모달 액션이 아래로 밀림 | 모바일 소개 영역 위치 조정, 메타데이터만 스크롤하고 모달 액션 유지 | 390px/1280px 캡처 및 bounding-box 검사 |

## 상태와 재사용의 경계

- Zustand: 사진, 카테고리, 좋아요, 데이터 로딩.
- URL: 공유/새로고침/브라우저 기록으로 복원할 탐색 조건. 외부 query와 hash 보존.
- Local state: 편집 입력, 선택 모드, 열린 Drawer/모달. 사진 모달 자체는 URL deep link 대상이 아니다.
- Session memory: 목록 스크롤. 새로고침 후 스크롤 복원은 보장하지 않는다.
- 파생값: 필터 결과, 좋아요 수, 앨범 개수·표지. 독립 전역 상태로 중복 저장하지 않는다.
- 지도 필터와 앨범 분류의 의미를 억지로 합치지 않는다. `PhotoSearch`의 조작, `PhotoFeed`의 사진 렌더링, `PhotoModal`의 상세 동작만 공유한다.

## 최적화의 범위

기존 피드 가상화, 이미지 thumbnail/full 분리, route lazy loading 유지. 좋아요 전용 중복 화면을 제거하고, 장소/태그별 반복 정렬 대신 그룹 집계를 사용했다. 시스템 앨범 표지는 기존 사진 순서 의미를 유지한다.

이는 코드 구조로 확인한 변경이다. 사용자 지연·FPS·LCP 개선율을 새로 측정한 결과는 아니다. 실제 사진 1,000장 실험은 이전 Commons 429 차단으로 별도 미완료이며, 일반 데모 16장과 성능 preview 6장 조건을 혼동하지 않는다.

## 재현

Frontend 디렉터리에서 Node 24와 설치된 Chrome으로 실행:

```powershell
npm run test:contracts
npm run test:demo
npm run typecheck
npm run build
```

- 계약/파생값 테스트: 30개 통과.
- 브라우저 회귀: 19개 통과. 가짜 API 실패·빈 결과·정상 결과, 예시 16장/성능 6장 유지, 탐색·접근성·반응형을 포함한다.
- TypeScript 및 production build 통과. 별도 lint 스크립트는 없다.
- 테스트 서버는 Playwright가 실행·종료한다. DB 쓰기나 운영 배포는 수행하지 않는다.
- 화면 캡처: `Frontend/test-results/frontend-{home,modal,albums}-{390,1280}.png`. `test:demo`로 재생성된다.
- 검증 한계: Chromium/Chrome 기준. 전체 사이트 WCAG 인증이나 모든 로그인/관리자 CRUD를 검증한 것은 아니다. 실제 원격 DB/지도 서비스의 가용성은 mock 회귀로 입증하지 않는다.
- 비차단 도구 경고: 오래된 Browserslist 데이터, Node의 기존 mixed module 형식 경고. 이번에는 의존성 버전이나 package module 형식을 바꾸지 않았다.

## 리뷰와 남은 작업

독립 읽기 검토 후 앨범 편집 버튼의 터치/키보드 가시성을 보완했다. seed/remote ID 충돌 제안은 현재 seed가 `demo-seed-*`, remote가 숫자 문자열임을 확인해 재현되지 않았다. 불필요한 저장 형식 마이그레이션은 추가하지 않았다.

별도 후속 범위: 실제 대량 사진 성능 실험, Firefox/Safari 검증, 전체 로그인/관리자 접근성, 원격 서비스 복구와 운영 배포.
